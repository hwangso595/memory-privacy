Memory privacy policy

Effective: August 16, 2026

Developer: DoubleMM

Memory is local by default. The app has no account requirement and does not collect, sell, or share your memories. It has no ads, tracking, behavioral telemetry, or crash-reporting service. It performs no background analytics. Only an answer-safety report you explicitly submit creates the limited anonymous counters described below. The other optional network action is the model download.

What stays on your device

Memory processes and stores the following inside its private app storage:

  • Memories you write or import, including text, dates, titles, people, places, and moods.
  • Local search indexes, embeddings, settings, commands, and installed Memory Pack state.
  • For photos you approve, a system-library pointer, limited metadata, and locally derived context. Memory does not create a durable second image or thumbnail archive.
  • If you choose a phone integration, minimized fields from calendars you select, names, organizations, and birthdays from contacts you select, or one rounded foreground location observation when you press Sync.

This information is stored in a SQLCipher-encrypted database. Its random key is held by the operating system’s secure credential storage. Search queries and generated answers are processed in memory and are not written to the archive. Search, embeddings, and answers run on the device.

Permissions

Optional features may ask for access to photos, selected calendars, selected contacts, or foreground location. You can deny or revoke these permissions in system Settings. Memory does not request background location, microphone, SMS, or call-log access. It does not use the camera.

Calendar actions are shown for confirmation before Memory creates or updates an event. Memory never deletes calendar events. Core writing and private search work without these permissions.

Network use

One optional data transfer is a 1.28 GB model-pack download. Before it starts, Memory shows this disclosure and asks you to confirm. If you confirm, Memory connects directly to Hugging Face to download the two model files. Hugging Face can receive standard connection data, including your IP address, device and user-agent information, and use of its download service. Memory sends no memories, questions, answers, photos, contacts, calendar data, or location. After the download, all inference runs on your device.

See the Hugging Face privacy policy for its handling of connection data.

Memory Cloud is not included or configured in the release covered by this policy. This release does not upload memory records to a Memory service. If a future release offers a cloud service, it will require explicit setup and updated disclosure before use.

Answer-safety reports

Every generated answer includes an optional in-app report action. Nothing is sent when you open the report form. If you choose a reason and press Submit report, Memory sends only the selected reason category, app version, and local model identifier. The report contains no prompt, answer, source, memory, photo, free text, account identifier, device identifier, email address, or location.

The HTTPS report service is hosted by Google Apps Script. Google can automatically receive ordinary connection data such as your IP address, user-agent information, and request time under the Google Privacy Policy. Memory requests omit cookies and developer-created account or device identifiers. For abuse prevention, the service keeps one anonymous per-minute submission count in Google Apps Script CacheService. That count contains no report fields or identifiers and expires within two minutes. The service also immediately adds accepted report fields to a daily anonymous aggregate counter. Outside the short-lived rate-limit count, the developer stores only those daily aggregate counters, not individual report bodies or per-submission timestamps, while needed to review answer quality and safety and improve on-device safeguards, then deletes them. Google may separately retain service or security logs, including request timing, under its privacy policy.

No ads or tracking

Memory has no general product analytics, advertising, tracking, behavioral telemetry, or crash-reporting endpoint. Its only developer-operated measurement is the anonymous aggregate counting created by an answer-safety report you explicitly submit, as described above. The developer cannot view your archive and may receive only the limited report and connection data described above. Memory does not sell personal data or share it with advertisers or data brokers.

If you explicitly export or share a file, the destination you choose receives that file and handles it under its own terms. Memory deletes and verifies removal of its temporary export copy after the share flow. Source documents selected for import are read locally; app-owned processing copies are removed and checked after import.

Gallery pointers and originals

Gallery integration is optional and removable. Disconnecting it removes Memory’s encrypted photo index, pointers, and derived records. It never deletes the original photos or videos in your system library. Those originals remain under your control in the Photos or gallery app.

Retention and erasure

Your local information remains until you remove it. In Settings → Storage and erasure, Memory provides:

  • Remove local models — removes complete and partial model files.
  • Erase archive; keep models — removes the encrypted archive, its key, app settings and integration state, temporary app files, and Memory-held document or photo access grants.
  • Erase everything from this device — removes the archive and downloaded models together.

These actions read back each included app-private boundary and show a receipt only after files and keys are verified absent. “Verified absent” means the named item is no longer present or readable through the app and operating-system APIs; mobile flash storage cannot guarantee forensic overwriting of physical cells.

Local erasure does not delete system-library originals, source files, exports saved elsewhere, operating-system permission grants, or existing device backups. Manage those separately. Android builds disable new Auto Backup copies, but the app cannot retract older or manufacturer-managed backups. On iOS, use Delete App, not Offload App, after completing in-app erasure if you also want to remove the app container.

Security

Memory limits data to app-private storage, encrypts its archive, and disables Android backup in current builds. No security measure is absolute; device compromise, operating-system backups, or files you export can fall outside Memory’s control.

Children

Memory is not directed to children under 13, and the developer does not knowingly collect personal information from children.

Policy access and changes

The app links to this page from Settings. Opening the link uses your browser; GitHub Pages may receive ordinary web connection logs under the GitHub Privacy Statement. Memory does not receive those logs.

If Memory’s data practices change, this page and its effective date will be updated before the changed practice is released.
